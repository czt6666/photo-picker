# PhotoPicker 网页版 + 远程相册

网页版就是 PhotoPicker 本身（同一套界面、快捷键、侧栏、网格、看图），跑在浏览器里；它没有本地图库，只看**远程相册**。
桌面版侧栏里也多了「远程相册」一栏：🔗 连接、＋ 创建，和网页版是同一份数据。

拿到链接（`https://你的域名/r/ABC234`）的人都能打开相册一起挑：星标大家共用，谁加的星会显示名字，
别人加星/取消在 1 秒内出现在所有人的屏幕上。

```
摄影师电脑                              服务器                          模特手机 / 平板 / 电脑
原图 35MB/张 ──压缩──▶  预览 2048px ≈0.4MB  ──────────────────▶  网格、看大图、加星
     ▲                  缩略 512px  ≈20KB                                 │
     │                  星标（SQLite，记下是谁加的）◀──── WebSocket 实时同步 ┘
     └── 桌面版在远程相册里「导出…」：按文件名对回本机原图（可带同名 RAW）
```

## 为什么这样设计

- **原图不上传。** 一次外拍 1000 张 JPG+RAW 约 35GB，家用宽带上行要传几个小时。压成 2048 像素的预览只有约 400MB，
  几分钟传完，手机上看也足够清楚。原图一直在摄影师电脑上，修图、导出都用原图。
- **压缩在上传的那台电脑上做。** 桌面版用 App 自带的解码器（认 RAW、HEIC）；网页版在浏览器里压，RAW 抠出相机内置的 JPEG 预览。
  服务器不解码图片，便宜的小服务器就够。
- **实时同步靠 WebSocket。** 普通网页是“问一次答一次”；WebSocket 是一条一直开着的电话线，服务器有新星标就主动推给相册里的每个人。
  断线（手机锁屏、换网络）会自动重连，重连后整份重新拉一遍，不会漏。
- **对回原图靠文件名。** 上传时记下每张在电脑上的文件夹、文件名和同名 RAW。在桌面版里，自己建的远程相册记得原图文件夹，直接拼路径；
  别人建的就在当前工作目录里按文件名找。

## 用法

- 创建：桌面版右键一个相册「共享为远程相册…」，或侧栏「远程相册」的 ＋；网页版点 ＋ 选文件夹/照片。建好后链接自动复制。
  传到一半关了，右键远程相册「继续上传…」，已传的会跳过。
- 连接：直接打开链接；或在侧栏点 🔗 粘贴链接/相册码；桌面版里在任何地方 ⌘V 粘贴链接也行。
- 挑：和本地相册一样，空格加星标，「已加星标的照片」看所有人挑出来的。第一次加星会问名字。
  手机上点格子看大图，左右滑翻页，双指捏放大，点两下 1:1。
- 导出原图：在桌面版打开远程相册 →「导出…」，跟本地相册一样复制原图（可勾同名 RAW）。
- 管理（只有创建者那台设备有权限）：右键远程相册 → 复制链接 / 改名 / 删除远程相册。别人只能「从列表中移除」。

## 部署

一个 Docker 镜像，数据在 `/data`（SQLite 数据库 + 预览图，备份这个文件夹即可）。镜像在**仓库根目录**构建，因为网页就是 App 的前端。

```bash
cd online
# 改一下 docker-compose.yml 里的 PP_CREATE_PASSWORD
docker compose up -d        # 打开 http://服务器IP:8080
```

### 部署在子路径下（czt666.cn 的做法）

网页和接口都放在 `https://czt666.cn/photo-picker/` 下：

1. 网页用 `PP_WEB_BASE=/photo-picker/ npm run build` 构建（资源路径带上前缀）。
2. 服务端照常跑在本机 `127.0.0.1:8081`，它不知道前缀。
3. Nginx 把 `/photo-picker/` 去掉前缀转给它，配置见 [nginx-photo-picker.conf](nginx-photo-picker.conf)；
   `http { }` 里还要有一句 `map $http_upgrade $connection_upgrade { default upgrade; '' close; }`（WebSocket 用）。

桌面发布版连的就是 `https://czt666.cn/photo-picker`（写在 `src/remote.ts` 的 `SERVER`），分享链接形如 `https://czt666.cn/photo-picker/r/ABC…`。

正式使用请在前面套 HTTPS（Caddy / Nginx），手机浏览器在 http 下不让复制链接，也不让网页全屏。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `PP_ADDR` | `0.0.0.0:8080` | 监听地址 |
| `PP_DATA_DIR` | `./data` | 数据目录 |
| `PP_WEB_DIR` | `../../dist` | 网页文件（仓库根目录 `npm run build` 的产物） |
| `PP_CREATE_PASSWORD` | 空 | 设了以后建相册要输这个密码，防止陌生人用你的服务器 |
| `PP_BEHIND_PROXY` | 空 | 前面套了 Nginx/CDN 时设为 `1`，按 `X-Forwarded-For` 认访客 IP |

桌面版连哪台服务器写死在代码里：本地调试 `http://localhost:8081`，发布版 `https://czt666.cn/photo-picker`。网页版就是打开它的那台。

容量估算：一张预览+缩略约 0.45MB，1000 张约 450MB。

## 开发

```bash
npm run build                                   # 仓库根目录：打包网页（dist/）
cd online/server && cargo run                   # 服务端 + 网页，http://localhost:8080
cd online/server && cargo test                  # 服务端接口测试（含 WebSocket 实时推送）
npx vitest run                                  # 前端单元测试（含 RAW 预览抠图、上传分组）
```
