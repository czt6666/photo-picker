# PhotoPicker 在线选片

摄影师上传照片，把 6 位**共享码**发给模特，模特在手机 / 平板 / 电脑浏览器里挑；选完摄影师下载**原图文件名清单**，回到电脑上对出原图去修。

```
摄影师电脑                         服务器                          模特手机
原图 35MB/张 ──浏览器里压缩──▶  预览 2048px ≈0.4MB  ──────────▶  滑着看、点 ♥
     ▲                          缩略 512px  ≈40KB                     │
     │                          选片记录（SQLite）  ◀──────────────────┘
     └── 清单 .txt（DSC_0001.JPG / DSC_0001.NEF …）──▶ 桌面版「导入清单…」加星标 → 导出原图
```

## 为什么这样设计

- **原图不上传。** 一次外拍 1000 张 JPG+RAW 约 35GB，家用宽带上行 30~50Mbps 要传两三个小时，服务器也得配大硬盘。
  压成 2048 像素的预览只有约 400MB，几分钟传完，手机上看也比屏幕清楚。
- **压缩在摄影师浏览器里做。** 服务器不用解码图片，便宜的小服务器就够；RAW 文件直接抠出相机内置的 JPEG 预览（浏览器不认 RAW）。
- **不卡的三个手段**：网格只加载 40KB 的缩略图且屏幕外不绘制；打开大图先把缩略图拉大垫底、预览图到了再盖上；同时预取下一两张。
  图片地址带自增 id、内容永不变，浏览器/CDN 可以缓存一年。
- **两边靠文件名对号。** 上传时记下每张在电脑上的文件夹和同名原图（JPG、RAW），导出的清单就是这些路径。

## 用法

- 摄影师：首页「我是摄影师」建相册 → 进管理页（**这个页面地址就是钥匙，收藏好**）→ 拖文件夹上传 → 「复制邀请」发给模特。
  中断了重新选同一个文件夹就是续传（已传的自动跳过）。
- 模特：打开链接 → 填名字 → 点 ♥ 选；大图里左右滑翻页、双击/双指放大、✎ 给摄影师留言；电脑上滚轮/方向键翻页、空格选中。
  同一个名字在手机和电脑上看到的是同一份选片。选完点「选好了」。
- 摄影师看结果：每个人选了哪些、是否提交、留言；可以「结束选片」锁定。
  - 「下载清单 .txt」→ PhotoPicker 桌面版打开这次拍摄的文件夹 → 右下角「导入清单…」→ 对上的原图加星标 → 「导出…」原图（可带 RAW）。
  - 「复制文件名」→ 粘到 Lightroom 等软件的文件名搜索里。
  - 「表格 .csv」→ 带留言的清单，Excel 直接打开。

## 部署

一个 Docker 镜像，数据在 `/data`（SQLite 数据库 + 预览图，备份这个文件夹即可）。

```bash
cd online
# 改一下 docker-compose.yml 里的 PP_CREATE_PASSWORD
docker compose up -d        # 打开 http://服务器IP:8080
```

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `PP_ADDR` | `0.0.0.0:8080` | 监听地址 |
| `PP_DATA_DIR` | `./data` | 数据目录 |
| `PP_WEB_DIR` | `./web/dist` | 网页文件 |
| `PP_CREATE_PASSWORD` | 空 | 设了以后建相册要输这个密码，防止陌生人用你的服务器 |
| `PP_BEHIND_PROXY` | 空 | 前面套了 Nginx/CDN 时设为 `1`，按 `X-Forwarded-For` 认访客 IP |

容量估算：一张预览+缩略约 0.45MB，1000 张约 450MB。旧相册在管理页底部删除。

## 开发

```bash
cd online/server && cargo run          # 服务端，:8080
cd online/web && npm install && npm run dev   # 网页，:5180，接口自动转到 :8080
cargo test   # 服务端接口测试（online/server）
npm test     # 网页单元测试：RAW 预览抠图、文件分组、清单导出（online/web）
```

共享码 6 位（去掉了易混的 0/O、1/I），同一 IP 10 分钟内输错 30 次会被暂时挡住，防止有人挨个猜。
